## 1. Overview

Budgets let users set spending limits per category for a given period (weekly, monthly, yearly). This feature implements the CRUD API for budgets, including an automatic calculation of the `spent` field by aggregating transactions in the same category within the budget's date range.

---

## 2. End Goal

When this feature is complete:

- `GET /api/budget` returns all budgets for the authenticated user, with real-time `spent` amounts calculated from actual transactions.
- `POST /api/budget` creates a new budget for a specific category and period.
- `PUT /api/budget/:id` updates a budget's amount, category, or date range.
- `DELETE /api/budget/:id` deletes a budget.
- Budgets have a computed `remaining` field (`amount - spent`).
- Users cannot create duplicate budgets for the same category + period overlap.

---

## 3. Product Requirements (PRD)

### 3.1 Functional Requirements

| ID     | Requirement                                                                      |
|--------|----------------------------------------------------------------------------------|
| FR-001 | `GET /api/budget` MUST return all budgets where `userId` matches the authenticated user. |
| FR-002 | For each budget, the `spent` field MUST be calculated by summing `amount` from all transactions where `userId` matches, `category` matches, `type` is `"expense"`, and `date` is between `startDate` and `endDate`. |
| FR-003 | Response MUST include a computed `remaining` field (`amount - spent`) for each budget. |
| FR-004 | `POST /api/budget` MUST accept `{ category, amount, period, startDate, endDate }`. |
| FR-005 | `POST /api/budget` MUST validate that `endDate` is after `startDate`.            |
| FR-006 | `POST /api/budget` MUST prevent overlapping budgets for the same category.       |
| FR-007 | `PUT /api/budget/:id` MUST verify ownership.                                     |
| FR-008 | `DELETE /api/budget/:id` MUST verify ownership.                                  |

## 5. Detailed Implementation Steps

### Step 1 — Model Enhancements (`server/src/models/Budget.ts`)

1. Uncomment the `remaining` virtual:
   ```typescript
   BudgetSchema.virtual("remaining").get(function () {
     return this.amount - this.spent;
   });
   ```
2. Uncomment the pre-save validation for `endDate > startDate`.
3. Ensure `toJSON` and `toObject` include virtuals:
   ```typescript
   { timestamps: true, toJSON: { virtuals: true }, toObject: { virtuals: true } }
   ```

### Step 2 — Implement `getBudgets`

This is the most complex handler — it needs to aggregate actual spending:

1. Get all budgets for the user.
2. For each budget, run a MongoDB aggregation on the `Transaction` collection:
   ```typescript
   const spentResult = await Transaction.aggregate([
     {
       $match: {
         userId: new mongoose.Types.ObjectId(req.user.id),
         category: budget.category,
         type: "expense",
         date: { $gte: budget.startDate, $lte: budget.endDate },
       },
     },
     { $group: { _id: null, total: { $sum: "$amount" } } },
   ]);
   ```
3. Set `budget.spent = spentResult[0]?.total || 0`.
4. Calculate `percentUsed`.
5. Return the enriched array.

**Performance tip:** Use `Promise.all()` to run all aggregations in parallel.

### Step 3 — Implement `createBudget`

1. Validate fields.
2. Check for overlapping budgets (same user, same category, overlapping date range).
3. Create and return.

### Step 4 — Implement `updateBudget` and `deleteBudget`

Standard ownership-verified update/delete (same pattern as transactions).
