## 1. Overview

This feature connects the frontend Login and Signup forms to the backend auth API, implements JWT storage in localStorage, adds an auth context/provider to track login state across the app, and updates the Axios interceptor to attach the token to every request.

---

## 2. End Goal

When this feature is complete:

- Users can register via the Signup form and are redirected to the Dashboard.
- Users can log in via the Login form and are redirected to the Dashboard.
- The JWT token is stored in `localStorage` and attached to all API requests.
- An `AuthContext` provides `user`, `login()`, `signup()`, `logout()` throughout the app.
- The Topbar and Sidebar display the real user's name and email.
- If the token is expired or invalid, the user is redirected to `/login`.
- Form validation shows inline errors for invalid inputs.

## 3. Product Requirements (PRD)

### 3.1 Functional Requirements

| ID     | Requirement                                                                       |
|--------|-----------------------------------------------------------------------------------|
| FR-001 | Signup form MUST call `POST /api/auth/register` with `{ name, email, password }`. |
| FR-002 | Login form MUST call `POST /api/auth/login` with `{ email, password }`.           |
| FR-003 | On success, the JWT token MUST be stored in `localStorage` under key `"token"`.   |
| FR-004 | On success, the user MUST be redirected to `/` (Dashboard).                       |
| FR-005 | On failure, an error message MUST be displayed below the form (e.g., "Invalid credentials"). |
| FR-006 | `AuthContext` MUST expose `{ user, token, isAuthenticated, login, signup, logout, loading }`. |
| FR-007 | On app load, `AuthContext` MUST check for an existing token in `localStorage` and call `GET /api/auth/me` to validate it. |
| FR-008 | `logout()` MUST remove the token from `localStorage` and redirect to `/login`.    |
| FR-009 | Axios request interceptor MUST attach `Authorization: Bearer <token>` to every request. |
| FR-010 | Axios response interceptor MUST catch `401` responses, clear the token, and redirect to `/login`. |
| FR-011 | Login form MUST validate that both email and password are provided before submitting. |
| FR-012 | Signup form MUST validate that passwords match and are at least 6 characters.     |
| FR-013 | Sidebar and Topbar MUST display the real user's name and email from `AuthContext`. |

### 3.2 Non-Functional Requirements

| ID      | Requirement                                                                     |
|---------|---------------------------------------------------------------------------------|
| NFR-001 | A loading spinner/state MUST be shown while authentication is being verified on app load. |
| NFR-002 | Token should NOT be logged to the console in production.                        |

## 5. Detailed Implementation Steps

### Step 1 — Create `AuthContext` (`client/src/context/AuthContext.tsx`)

```typescript
interface AuthContextType {
  user: { id: string; name: string; email: string } | null;
  token: string | null;
  isAuthenticated: boolean;
  loading: boolean;
  login: (email: string, password: string) => Promise<void>;
  signup: (name: string, email: string, password: string) => Promise<void>;
  logout: () => void;
}
```

1. On mount, check `localStorage` for a token.
2. If found, call `GET /api/auth/me` to validate and get user data.
3. If valid, set `user` and `isAuthenticated = true`.
4. If invalid (401), clear the token.
5. Set `loading = false` when done.

### Step 2 — Implement API Functions (`client/src/api/auth.ts`)

Replace the `throw new Error("Not implemented yet")` with actual Axios calls:
```typescript
export const loginUser = async (payload: LoginPayload): Promise<AuthResponse> => {
  const response = await api.post("/auth/login", payload);
  return response.data;
};
```

### Step 3 — Implement Axios Interceptors (`client/src/api/axios.ts`)

Uncomment the commented interceptor code:
- **Request interceptor:** Read token from `localStorage`, attach to headers.
- **Response interceptor:** On 401, clear token and redirect to `/login`.

### Step 4 — Connect Login Page

1. Import `useContext(AuthContext)`.
2. In `handleSubmit`, call `login(email, password)`.
3. On success, `useNavigate()` to redirect to `/`.
4. On error, set an error state and display it.

### Step 5 — Connect Signup Page

Same as Login, but call `signup(name, email, password)`.

### Step 6 — Update Layout Components

Replace hardcoded "John Doe" / "john@example.com" with `user.name` / `user.email` from context.
