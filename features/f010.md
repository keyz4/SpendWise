---

## 1. Overview

This feature connects the Budget page to the real API, replaces mock data, adds a "Create Budget" modal, and implements Edit/Delete functionality. The visual budget cards with progress bars already exist — they just need real data behind them.

---

## 2. End Goal

When this feature is complete:

- Budget cards display real data fetched from `GET /api/budget`.
- The `spent` amounts reflect actual transactions (computed by the backend).
- Progress bars accurately show the percentage of budget used.
- Users can create a new budget via a modal form.
- Users can edit (change amount, dates) or delete existing budgets.
- Budgets nearing/exceeding their limit show visual warnings (already implemented in UI).
- Empty state shown when no budgets exist.

---

## 3. Product Requirements (PRD)

### 3.1 Functional Requirements

| ID     | Requirement                                                                      |
|--------|----------------------------------------------------------------------------------|
| FR-001 | On page load, fetch budgets from `GET /api/budget`.                              |
| FR-002 | Render one budget card per budget with real `amount`, `spent`, `remaining`, and `percentUsed`. |
| FR-003 | "Create Budget" button MUST open a modal with: category (dropdown), amount, period (weekly/monthly/yearly), start date, end date. |
| FR-004 | Modal MUST validate that end date > start date and amount > 0.                   |
| FR-005 | On submit, call `POST /api/budget`, close modal, refresh list.                   |
| FR-006 | Each card MUST have an overflow menu or buttons for Edit / Delete.               |
| FR-007 | Edit opens the modal pre-filled with existing budget data.                       |
| FR-008 | Delete shows confirmation before calling `DELETE /api/budget/:id`.               |
| FR-009 | Show loading state while fetching budgets.                                       |
| FR-010 | Show empty state ("No budgets created yet") when the list is empty.              |

## 5. Detailed Implementation Steps

### Step 1 — Implement API Functions

Replace `throw` statements in `client/src/api/budget.ts` with real Axios calls.

### Step 2 — Create `BudgetModal` Component

Fields:
- **Category**: dropdown from categories API (expense categories only)
- **Amount**: number input
- **Period**: dropdown (weekly / monthly / yearly)
- **Start Date**: date picker
- **End Date**: date picker (must be after start date)

### Step 3 — Rewrite `Budget.tsx`

1. Fetch budgets on mount.
2. Map over real data instead of `mockBudgets`.
3. Add Edit/Delete buttons to each card (e.g., a small `⋮` menu or icon buttons).
4. Wire modal open/close states.
